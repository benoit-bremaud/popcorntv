# Operate the signed local gate

Issue #329 replaces disabled hosted workflows with repeatable local checks and signed exact-head merge evidence.

## Setup and prerequisites

Supported operator environment: Linux, Python >=3.11, Git, SSH signing/agent, Docker,
FFmpeg, Chromium for the workspace's Playwright version, and a reachable local SonarQube
Community instance with `sonar-scanner` on PATH. This migration installs no service or
scheduled task and deploys nothing. GitHub access is needed for publication/verification;
the checks themselves execute locally. External vulnerability/rule databases may require
network access, and unavailable required scans fail.

Use `mise x -- just setup` to install the locked tools, frozen workspace dependencies and
Lefthook hooks. `mise.lock` references generated `.mise/locks` backend files: commit these
together and do not reformat their generated bytes. Node 22.23.4 and npm-backed pnpm
10.30.3 replace the previous standalone pnpm/temporary wrapper. The installed mise bootstrap
version is 2026.10.23; record upgrades explicitly. Other installed global tools are not used
as substitutes for this project's pins.

Configure this clone with `git config --local gpg.format ssh` and
`git config --local user.signingkey /path/to/primary-key.pub`. Load the corresponding private
key through the existing SSH agent. Never put a private key in this repository. The owner's
option A public identity was merged in PR #334; new identities or revocation require a
reviewed `.github/allowed_signers` change on main before use.

Sonar reads `SONAR_TOKEN` from the environment, or a private mode-600 file selected by
`SONAR_TOKEN_FILE`; the default is `$XDG_CONFIG_HOME/sonarqube/analysis-token` (otherwise
`~/.config/sonarqube/analysis-token`). `SONAR_HOST_URL` defaults to localhost:9000. Tokens
are passed only through the scanner's environment and are not written to the run manifest.
The gate does not load `.env`, `.env.staging` or real application data.

## Normal workflow

1. Commit reviewed explicit paths. Pre-commit runs `mise x -- just fast`; commit-msg enforces
   Conventional Commits. Partially staged files are refused, avoiding checks of bytes other
   than those committed. Staged secrets are checked from the index with redacted Gitleaks.
2. Run `mise x -- just check` before push. The hook runs the same command. It includes a
   frozen installation, types/lint/format, infrastructure tests, hook/script validation,
   history secret scan, OSV, Semgrep CE and each required application test package.
3. Push, then run `mise x -- just gate` on that exact clean head. It confirms origin
   publication and pending status, captures prerequisite versions, runs check, builds,
   waits for Sonar, executes production-build browser smoke, scans source/config/image,
   emits an SBOM and publishes the verified signed note followed by success status.
4. Inspect the local adversarial review and all actual PR review comments. Run
   `mise x -- just merge PR_NUMBER` only after review acceptance. The command locks the same
   repository as gate, verifies current head/status/signature and submits a SHA-pinned merge.

All initial-migration gates run container checks, even when the old path filter would not
apply. No required step is skipped. Browser tests remain API-stubbed smoke, not real movie
acquisition QA. The existing Makefile staging/deployment commands are unchanged and are
not invoked by gate or merge. A squash creates a different main SHA, which needs a fresh
gate before any later authorized deployment.

## Evidence and failure behavior

Application suites run sequentially with at most four workers each and `FFMPEG_IT=1`.
Fresh Vitest JSON reports require a nonempty all-passed result and reject pending/todo,
failed or exclusive tests. The checked unittest runner rejects empty suites, skips and
expected failures. Playwright has zero retries, forbids exclusive tests and its fresh JSON
report must contain only tests that passed once, with no skips, unexpected/flaky/interrupted
results or expected failures. Existing fixture timeouts are unchanged.

Each gate retains `.git/local-ci-runs/<UTC>-<sha>-<pid>/` with its head, prerequisite version
manifest, per-step output, timing/exit records, test reports and final result. Keep failed
runs when investigating; a later successful run does not erase them. Trivy outputs and SBOM
are under ignored `.trivy/`. Logs remain local; inspect/redact before sharing. Individual
check output is also visible in the invoking terminal. No environment dump is captured.

Gate and merge use one advisory OS lock in the common Git directory, covering linked
worktrees. Concurrent operations are refused. One operator/machine is supported; do not
run independent machines concurrently. Missing tools and failed required scans cannot
produce success. If pending cannot be confirmed, checks never start and prior valid remote
evidence is not claimed revoked. After pending succeeds, failure/interruption leaves a
non-success state; a failed live read blocks merge. Do not bypass the guard or erase evidence.

The accepted [protocol and workflow inventory](local-gate-protocol.md) document removed
GitHub-only engines honestly: Semgrep/OSV/local review are alternatives, not identical
CodeQL/dependency-review/Scorecard engines. No Actions or hosted review is requested.

## Validation boundaries

[Designed cases](../qa/cases/329-signed-local-gate.md) map the security and orchestration
tests. Infrastructure tests use real Git/SSH with only external transports/CLI tools
substituted; separate real Gitleaks, Vitest, pnpm and installed-hook fixtures test those
boundaries. These tests are required by check. No unrelated live acquisition, personal
credential replay or deployment belongs to this gate migration.
